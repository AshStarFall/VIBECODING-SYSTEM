# Resource and System Maintenance

## Review cadence

Review resources when they are selected for a real project and periodically when the system is actively used. Check time-sensitive providers, security tools, MCP servers, platform policies, and pricing before each adoption. Do not imply that a scheduled review guarantees all links are current.

## Review a candidate

1. Resolve the canonical upstream and official documentation.
2. Check recent releases/maintenance, supported versions, open security advisories, license, ownership, and compatibility.
3. Review permissions, data sent/stored, deployment needs, pricing/quotas, and exit/migration cost.
4. Compare one simpler alternative and one plausible competitor.
5. Update the resource card's verification date and factual notes; remove or mark superseded links when appropriate.

## Improve this system

- Capture repeated project failures as a concise rule plus a way to verify it.
- Remove duplicate advice and stale provider-specific claims.
- Keep templates small enough that teams will use them; make high-ceremony steps risk-triggered.
- Do not preserve social screenshots as the source of truth. Record attributable facts and canonical links only.
- Periodically test the copy/paste starter prompt on a fresh, representative project and note friction.
