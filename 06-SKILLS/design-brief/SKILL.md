# Design Brief

1. Inspect existing UI, design tokens, audience, content, and primary user flow.
2. State the screen hierarchy, responsive behavior, navigation, important states, and accessibility needs.
3. If there is no established system, propose a palette, typography, spacing, and motion principles with rationale. Avoid generic templates and decoration without purpose.
4. Specify empty, loading, error, success, and permission-denied states relevant to the flow.
5. Save the approved brief in the project. Build the smallest usable flow and inspect it at relevant viewports.
6. Verify keyboard operation, focus, semantics, contrast, text overflow, and real content before calling it complete.

Do not blindly apply a hard-coded aesthetic when the product already has a design system or the user has supplied a design.
